# Language-path verification and language-sensitivity tests (Phase 2)

All numbers are produced by scripts in `scripts/` and stored as JSON/CSV under `audit/` and `training/`. Frozen 10-task checkpoints are read-only baselines.

## 1. Verified path of the instruction text (source-level + executed)

1. RoboTwin instruction string (`env.set_instruction`, generated by RoboTwin's `generate_episode_descriptions`, seen split) -> policy batch key `task`.
2. `policy_preprocessor.json`: `smolvla_new_line_processor` appends `"\n"`, then `tokenizer_processor` (tokenizer folder inside the checkpoint, max_length 48, padding `longest`, truncation). `scripts/trace_tokens.py` executes this on real instructions, e.g. "Tap the top center of the blue dome-shaped bell." -> 14 tokens (`T ap Ġthe Ġtop Ġcenter Ġof Ġthe Ġblue Ġdome - shaped Ġbell . Ċ`); the stack instruction pair "stack green block above red block" / "stack red block above green block" -> 19 tokens each with `Ġgreen`/`Ġred` swapped, so the two counterfactual instructions are distinguishable at token level.
3. `modeling_safediff_vla.py::_encode_multimodal_latent`: `embed_prefix(images, lang_tokens, state)` + one pass of the frozen SmolVLM prefix; image tokens precede the language tokens in the prefix, so language-row states can attend to image tokens. `compute_prefix_modality_ids` marks language rows `mod == 1`.
4. HR scorer input = the `mod == 1 & pad` rows (`tok[0][mask]`), in `v21_rt_policy.score` (runtime) and `build_v21_cache_10.py` (training cache) - same code path, 14-19 rows x 960.
5. `v21rt.Scorer` (original `v21hr_candidate.Scorer("B")`): `txt` Linear -> attention-pooled query `q` (learned query attends the language rows) ; candidate vector = attention-pooled 64 crop tokens of a 72 px head-camera crop at each proposal ; logit_i = <Wq q, Wv v_i>/sqrt(d).
6. argmax over head-camera proposals -> selected referent proposal -> (wrist views) Hungarian two-ray association -> triangulation -> AnchorHead -> grasp xyz.

## 2. Offline language-sensitivity of the frozen 10-task scorers (identical visual candidates; `scripts/lang_probe_offline.py`, `audit/lang_probe_offline.json`)

Cached frames of each task (train/val of the 10-task study). `shuffled` = language states of a different scene (different paraphrase), `blank` = one zero text token.

| task | split | n | chance | acc orig | acc shuffled | acc blank (visual only) | top-1 flips under shuffled |
|---|---|---|---|---|---|---|---|
| click_bell | val | 104 | 0.33 | 1.000 | 1.000 | 1.000 | 0 |
| place_container_plate | val | 148 | 0.33 | 1.000 | 1.000 | 1.000 | 0 |
| stack_blocks_two | val | 345 | 0.28 | 1.000 | 1.000 | 1.000 | 0 |
| handover_block | val | 337 | 0.34 | 1.000 | 1.000 | 1.000 | 0 |

(train rows identical in the JSON.) For stack the cycle embedding is the only non-visual driver: flipping the cycle index drops accuracy to 0.08 (val) with 92 % top-1 flips.

Reading (fact): all four frozen scorers select the referent from the crop appearance (plus the cycle index for stack) and ignore the instruction. This is a consequence of the training data: within a task there is one instructed referent class, so correct accuracy does not require language (the point raised in the task description). These numbers do **not** show a causal effect of language, and they do not show that language is harmful.

## 4. Counterfactual target-switch accuracy (held-out CF val scenes; scorer-level, no simulator rollout)

Metric: top-1 accuracy over (scene, instruction) samples; `both` = both referents of a scene correct (same scene, instruction switched); chance = 1/K over valid candidates. Source: `training/scorer_{task}_{mode}_v1.json`.

| task | scorer | acc | both-correct | acc (instr. A) / (instr. B) | shuffled language acc | blank acc |
|---|---|---|---|---|---|---|
| click_bell (n=20 scenes, 80 samples) | frozen 10-task baseline | 0.500 | 0.00 | 0.5 / 0.5 | 0.50 | 0.50 |
| click_bell | CF-trained (paired) | 1.000 | 1.00 | 1.0 / 1.0 (arm and no-arm both 1.0) | 0.45 | 0.50 |
| click_bell | control (same data, unpaired) | 1.000 | 1.00 | | 0.45 | 0.50 |
| stack_blocks_two (n=15 scenes, 30 samples) | frozen 10-task baseline | 0.500 | 0.00 | orig 1.0 / swap 0.0 | 0.50 | 0.50 |
| stack_blocks_two | CF-trained (paired) | 1.000 | 1.00 | 1.0 / 1.0 | 0.63 | 0.50 |
| stack_blocks_two | control (unpaired) | 1.000 | 1.00 | 1.0 / 1.0 | 0.67 | 0.50 |

Original-distribution val accuracy is unchanged (click 1.000 vs 1.000; stack 0.991 CF / 1.000 control vs 1.000 baseline; 345 val samples).

Findings (facts within these data): (i) the frozen baseline has 0 % counterfactual target-switch (it always returns its single visual/cycle prior); (ii) the original counterfactual recipe makes the scorer follow the instruction (100 % on held-out scenes, accuracy falls to near chance with shuffled language, proving the instruction is used); (iii) the unpaired control reaches the same held-out switch accuracy, so same-scene pairing per batch is not necessary for this effect: any training set in which the referent varies with the instruction while the visual prior is balanced is sufficient. The scorer-level result is only evidence about language use; its effect on native success is evaluated in the development ablations (`DEVELOPMENT_ABLATIONS.csv`).

Caveats: CF val sets are small (15 and 20 scenes); stack CF covers cycle 0 only; click_bell arm words are an independent positional cue (no-arm variants control for it and also reach 1.0).
